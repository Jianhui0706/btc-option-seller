# 双策略 TradingView 接入测试指南

## 测试目标

用同一个 Webhook 接收两套 TradingView Pine 策略，并在后端分别显示：

- `BTC期权卖方_项目规范策略A`：项目规范策略 A；
- `BTC期权卖方_宽松对照策略B`：入场宽松策略 B。

两套策略使用不同的 `strategy` 和 `tv_id`，但共用同一个账户、Webhook URL 和口令。

## 两套策略的区别

策略 A 严格保持项目规范的入场门槛：

- BTC 2 小时 K 线收盘确认；
- DVOL 档位：40 / 60 / 85；
- `abs(CCI20) < 101`；
- HV 分位不低于 30%；
- PUT/CALL 布林带破轨并反向收线；
- DVOL 退出：最近 60 天 12 小时数据的 30 分位。

策略 B 只放宽入场门槛：

- DVOL 档位：35 / 55 / 80；
- `abs(CCI20) < 120`；
- HV 分位不低于 25%。

策略 B 的 K 线周期、布林形态、DVOL 退出、卖腿 Delta、DTE、分组、对冲和风险参数与策略 A 相同。

## 开始前的安全设置

1. 确认后端是 `TESTNET`。
2. 在系统页面点击“暂停新开仓”。
3. 暂停或删除之前重复创建的 TradingView Alert。
4. 从图表删除旧的重复 Pine 实例，只保留本次测试的 A 和 B。

暂停新开仓不会阻止 Webhook 接收。后端仍会记录信号，只是不执行开仓，因此适合先验证多策略归属。

## 创建策略 A

1. 打开 BTCUSDT 图表，周期设为 3 分钟。
2. 打开 Pine 编辑器，新建空白策略。
3. 粘贴 `pine/tv_strategy_a_standard.pine` 的全部内容。
4. 保存名称建议使用：`BTC期权卖方V2_规范A`。
5. 点击“添加到图表”。
6. 打开策略参数，确认“启用真实 OPEN/CLOSE 测试信号”保持关闭。
7. 打开系统“TV 接入”页面。
8. 策略名称填写：`BTC期权卖方_项目规范策略A`。
9. 点击“为新警报生成 ID”。
10. 复制 Webhook URL 和完整 Alert JSON。
11. 在 TradingView 创建警报：
    - Condition：`BTC期权卖方·项目规范策略A`；
    - 类型：`订单成交和 alert() 函数调用`；
    - 名称：`BTC期权卖方_项目规范策略A_测试`；
    - Webhook URL：粘贴系统地址；
    - Message：粘贴策略 A 的完整 JSON。
12. 创建一次即可。

## 创建策略 B

1. 在 Pine 编辑器新建另一个空白策略。
2. 粘贴 `pine/tv_strategy_b_relaxed.pine` 的全部内容。
3. 保存名称建议使用：`BTC期权卖方V2_宽松B`。
4. 点击“添加到图表”。
5. 打开策略参数，确认“启用真实 OPEN/CLOSE 测试信号”保持关闭。
6. 回到系统“TV 接入”页面。
7. 策略名称改为：`BTC期权卖方_宽松对照策略B`。
8. 再次点击“为新警报生成 ID”。B 不得复用 A 的 `tv_id`。
9. 复制新生成的完整 Alert JSON。
10. 在 TradingView 创建第二个警报：
    - Condition：`BTC期权卖方·宽松对照策略B`；
    - 类型：`订单成交和 alert() 函数调用`；
    - 名称：`BTC期权卖方_宽松对照策略B_测试`；
    - Webhook URL：与 A 相同；
    - Message：粘贴策略 B 的完整 JSON。

## 验证结果

两份测试 Pine 会在新 Alert 创建后的首根实时 3 分钟 K 线收盘时发送一次 STATUS，之后按 2 小时周期发送连接回报。

进入系统“策略信号”页面，应看到两张策略卡片：

- `BTC期权卖方_项目规范策略A`
- `BTC期权卖方_宽松对照策略B`

进入“信号日志”，展开记录并核对：

- `strategy` 分别属于 A 和 B；
- STATUS 连接回报不触发交易，其中 `tv_id` 显示 `—` 属于正常现象；
- A、B 的 Alert JSON 中应使用不同的 `tv_id`；
- 真实 OPEN/CLOSE 信号会显示不同的 `tv_id`，并生成各自的 `signal_id`。

确认两套策略均能稳定收到连接回报后，才点击系统“恢复新开仓”。如果 A 和 B 同时产生开仓信号，后端会记录两条，但由于项目规则规定账户同一时间只能存在一笔卖方期权交易，通常只有第一条能继续执行，另一条会因已有卖方仓位被拒绝。

## 第二阶段：启用真实测试信号

1. 在策略 A 或 B 的参数中开启“启用真实 OPEN/CLOSE 测试信号”。
2. 删除该策略原来的 Alert。
3. 重新生成 `tv_id` 和 Alert JSON，并重新创建 Alert。
4. 确认系统仍为 TESTNET，再恢复新开仓。
5. 建议一次只启用一个策略测试真实执行；待仓位完整关闭后，再测试另一个。

TradingView Alert 保存的是创建时的 Pine 参数快照，因此只修改图表参数、不重建 Alert，不会让服务器上的旧 Alert 获得新开关状态。
