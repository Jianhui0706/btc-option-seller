# 对冲激活系数与期权期限参数化 — 改造方案

> 状态：**已实现**。口径见第五节，落地方案见第六节，落地清单见第八节。
> 日期：2026-08-05

> 2026-08-06 补充：激活判断已改为订阅 Deribit `deribit_price_index.btc_usd`
> 实时指数价逐笔比较；3 分钟扫描只作为激活兜底，并继续负责撤销确认与完整风控。

## 一、需求原文（四点）

1. **sell call spread（CALL_CREDIT）**：`x = |开仓时BTC − BEP| × 0.2`；当 BTC 当前价超过 `开仓BTC价格 + x` → 启动动态对冲。
2. （原文无第 2 点）
3. **sell put spread（PUT_CREDIT）**：当 BTC 当前价小于 `开仓时BTC价格 − x` → 启动动态对冲。
4. **开仓选择的期权期限变成一个参数**，直接按期限来选；如果没有设置该参数，按原代码执行。

附加要求：**`0.2` 作为参数接口暴露在前端，可以自行调控。**

---

## 二、需求理解（确认口径）

| 点 | 含义 |
|---|---|
| 第 1 点 | CALL_CREDIT：`x = |开仓指数价 − BEP| × 0.2`，现价 > `开仓价 + x` 时启动对冲 |
| 第 3 点 | PUT_CREDIT：现价 < `开仓价 − x` 时启动对冲 |
| `0.2` | 做成前端可调参数 |
| 第 4 点 | 开仓期权期限做成参数，直接按期限选；不填走原逻辑 |

---

## 三、关键发现：第 1、3 点现有代码已经是这套机制（系数为 0.5）

当前对冲激活价的计算在 [`bep.py:22`](../web/backend/src/engine/bep.py#L22)：

```
activation_price = 开仓指数价 + (BEP − 开仓指数价) × progress
```

其中 `progress` 即配置项 `bep_activation_progress`，**当前默认 0.50**（见 [`base.yaml:38`](../web/backend/config/base.yaml#L38)）。

触发判断在 [`bep.py:30`](../web/backend/src/engine/bep.py#L30)：

- CALL_CREDIT：`bar_close ≥ activation_price`
- PUT_CREDIT：`bar_close ≤ activation_price`

### 与需求公式的等价性证明

需求的 `x = |开仓价 − BEP| × 0.2`，代入现有公式（把 `progress` 取 0.2）：

- **CALL**（BEP > 开仓价）：`开仓价 + (BEP − 开仓价)×0.2 = 开仓价 + |开仓价 − BEP|×0.2 = 开仓价 + x` ✓
- **PUT**（BEP < 开仓价）：`开仓价 + (BEP − 开仓价)×0.2 = 开仓价 − |开仓价 − BEP|×0.2 = 开仓价 − x` ✓

**结论**：第 1、3 点的公式与现有 `activation_price()` 完全等价，区别只在系数 `0.5 → 0.2`。逻辑本身无需改写，改的是"参数值 + 参数来源"。

### ⚠️ 连带影响：撤销线会一起前移

对冲撤销线（[`bep.py:45`](../web/backend/src/engine/bep.py#L45)）从激活价派生：`release_line = activation_price × 0.98(CALL) / 1.02(PUT)`。激活价往开仓价方向靠（0.5 → 0.2），撤销线随之前移，"启动对冲 → 撤销对冲"的价格带整体更贴近开仓价。已确认可接受。

## 四、第 4 点：期权期限选择现状

当前期限**间接**由 DTE 区间决定：

1. 档位表 `tier_map` → `{dte_lo, dte_hi}`（[`base.yaml:13`](../web/backend/config/base.yaml#L13)）
2. [`orchestrator.py:84-104`](../web/backend/src/engine/orchestrator.py#L84) 取得 DTE 区间（信号可带 `dte_min/dte_max`，否则用 tier 映射）
3. [`market_data.option_chain_tickers()`](../web/backend/src/exchange/market_data.py#L121) 在区间内挑**最接近区间中点、且至少两条双边报价**的到期日

"按期限选"即绕过区间、直接锁定目标到期日。

## 五、已确认决策

| # | 决策 | 结论 |
|---|---|---|
| ① | 参数存放 / 前端怎么调 | **方案 A：全局运行时设置**。前端可随时改，引擎每轮实时读，`base.yaml` 作默认值。**两个新参数（激活系数 + 期限）都按此模式。** |
| ② | 激活系数默认值 | 不设置时默认 **0.2**；前端改了用改后的值。`base.yaml` 的 `bep_activation_progress` 默认由 0.50 改为 **0.20**，前端 state 覆盖优先。 |
| ③ | 期限口径 | **具体到期日**。 |
| ③-a | 期限输入方式 | 前端**下拉**，列表来自后端拉取的 Deribit 当前实际挂牌到期日。 |
| ③-b | 期限回退规则 | **设了期限 → 严格按该到期日选腿**；该到期日凑不出合格双腿 → 沿用现有 `REJECT_NO_VALID_LEGS`（该单不开 + 告警），**不静默改到别的到期日**。**未设 → 原 tier/DTE 逻辑。** |

### 隐患提示（已知悉）

"具体到期日 + 全局设置"意味着这个日期是**一次性**的：它到期后，之后的开仓会因该到期日已下市而命中"凑不出合格双腿 → 不开单"。需要使用者在到期后手动更新下拉选择。前端下拉只列当前挂牌到期日，可显著降低误填风险。

## 六、实现方案

### 6.1 后端

1. **默认值**：[`base.yaml`](../web/backend/config/base.yaml) `bep_activation_progress: 0.50 → 0.20`。
2. **运行时设置存储**：用现有 `state` 表存两个键
   - `runtime.bep_activation_progress`（数字，(0,1]）
   - `runtime.forced_expiry_ts`（到期日时间戳；空 = 不指定）
   启动时载入 `Ctx`，前端写入时同步更新 `Ctx`（避免热路径频繁读库）。
3. **激活系数生效点**：[`hedge.hedge_price_levels()`](../web/backend/src/engine/hedge.py#L109) 现读 `ctx.cfg.hedge.bep_activation_progress`，改为优先读 `Ctx` 上的运行时系数，回退 cfg 默认。
4. **期限生效点**：[`orchestrator.py`](../web/backend/src/engine/orchestrator.py) 选腿处（及 `reverser` 的开仓路径）——
   - 若 `forced_expiry_ts` 有值：锁定到该到期日（把 DTE 区间收成该到期日单点，或给 `option_chain_tickers` 传精确到期日做匹配）；选不到合格双腿则维持现有 `REJECT_NO_VALID_LEGS`。
   - 若为空：走原 tier/DTE 逻辑。
5. **新 API**（[`api.py`](../web/backend/src/api.py)）：
   - `GET /api/runtime_settings`：返回当前系数、当前期限、**可用到期日列表**（拉 Deribit `get_instruments` 汇总 `expiration_timestamp`）。
   - `POST /api/runtime_settings`：设置 / 清空系数与期限，写 `state` 表 + 更新 `Ctx`。
6. **校验**：系数 ∈ (0,1]；期限必须是当前挂牌到期日之一（否则拒绝写入）。

### 6.2 前端

- 新增"参数设置"小面板：
  - 数字输入框：对冲激活系数（占位/默认 0.2）
  - 下拉框：开仓到期日（含"不指定 = 原逻辑"项）
  - 保存 / 清空按钮，调 `POST /api/runtime_settings`
- 面板载入时调 `GET /api/runtime_settings` 回填当前值与到期日下拉项。

### 6.3 测试

- 更新对默认系数的断言：`test_hedge_activation.py`、`test_bep.py`（0.50 → 0.20）。
- 新增：运行时系数覆盖生效、强制到期日选腿命中 / 未命中（回退 `REJECT_NO_VALID_LEGS`）、`runtime_settings` API 读写与校验。
