# BTC 期权卖方策略 V2 — 运行手册

## 系统组成

```
TradingView (pine/btc_credit_spread_v2.pine, 挂3分钟图)
    │  webhook: OPEN_REQUEST / EXIT_DVOL (JSON, passphrase 鉴权)
    ▼
后端 web/backend/ (Python asyncio + FastAPI, 端口 8300)
    │  单 worker 命令队列: 强平 > 平仓 > 对冲撤销 > 对冲调整 > 扫描 > 开仓
    │  3分钟扫描: 持仓核对→风控→DVOL退出→BEP→对冲
    │  SQLite: web/backend/data/seller_v2.db
    ▼
Deribit (testnet / mainnet): 期权双腿 + BTC-PERPETUAL 对冲
```

## 本地开发启动

```bash
# 首次安装
python -m pip install -r web/backend/requirements.txt
cd web/frontend
npm install

# 终端一：后端
cd web/backend
python server.py --reload

# 终端二：前端
cd web/frontend
npm run dev
```

开发页面：`http://127.0.0.1:5173`；Vite 自动将 `/status`、`/account`、
`/control/*` 等接口代理到 `http://127.0.0.1:8300`。

连接和测试：

```bash
cd web/backend
python scripts/check_connectivity.py
python -m pytest -q
```

## 单端口运行 / 部署

```bash
cd web/frontend
npm run build               # 构建到 web/backend/static/
cd ../backend
python server.py            # 同时提供 API 和构建后的前端，端口 8300
```

开发时使用 `npm run dev`；部署时不需要长期运行Vite，只需要先构建一次。

`.env` 的 `DERIBIT_ENV=testnet|mainnet` 决定环境；策略参数在 `config/base.yaml`，
环境覆盖在 `config/testnet.yaml` / `config/mainnet.yaml`（mainnet 禁止 debug 旁路）。

首次启动后必须手动开启交易（默认关闭）：
```bash
curl -X POST "http://HOST:8300/control/trading?enabled=true"
```

## TradingView 配置

1. 打开 BTC 图表（建议 `DERIBIT:BTCUSD` 或 BTC-PERPETUAL），周期切到 **3 分钟**；
2. 加载 `pine/btc_credit_spread_v2.pine`（Pine v6）；
3. 参数页填 `passphrase` = 后端 `.env` 的 `WEBHOOK_PASSPHRASE`；
4. **等图表加载完整历史后**（DVOL 分位需要 730 天 × 2 根 12h bar，需 Premium 级历史深度，
   右上角状态表 "DVOL样本" 显示 1460/1460 才达标）再创建 Alert：
   - Condition: 本指标 → "任何 alert() 函数调用"
   - Webhook URL: `https://你的域名/webhook/tradingview`
   - 消息体留空（alert() 已自带 JSON）
5. TradingView webhook 只支持 80/443 端口，云服务器需配 HTTPS 反代（Caddy/Nginx）。
6. 保持参数页的「每根2h bar上报心跳」为开启（默认开）。心跳每 2 小时发一条
   `event=STATUS` 到同一个 webhook，供信号中心的「开仓条件实时看板」显示
   Pine 真实算出的数值。**它同时是链路存活证明**：口令填错时后端会静默丢弃
   （见 `src/webhook.py` 的鉴权分支，不写库不发事件），此时看板会提示
   "尚未收到 Pine 心跳" —— 否则这类配置错误要等到几天后信号没来才会被发现。

> 改过 Pine 脚本后，图表上的指标要重新加载，**已有 Alert 需要删掉重建**，
> 否则 Alert 仍绑定旧版脚本，不会发心跳。

## 开仓条件实时看板

信号中心页顶部并排显示两列：

| 列 | 数据源 | 用途 |
|---|---|---|
| 后端自算 | Deribit BTC-PERPETUAL 2h K 线 | 常驻可用，TradingView 挂了也能看市场条件 |
| Pine 心跳 | TradingView 图表符号（如 BTCUSDT） | 决定信号发不发的真值 + 链路存活证明 |

两列数值会有小幅偏差（价格序列不同），属正常。判定优先级：

- **DVOL 档位**永远以后端为准 —— Pine 在 3 分钟图上凑不满 730 天窗口，
  主动发 `tier=-1` 交给后端权威判定。看板若只看 Pine 会误报"档位通过"，
  而实际后端会以 `REJECT_DVOL_BELOW_ENTRY` 拒掉已发出的信号。
- 其余四项心跳新鲜（≤150 分钟）时以 Pine 为准，否则退回后端自算。

后端复现用的参数在 `config/base.yaml` 的 `entry_signal`，**必须与 Pine 的
`grpSig` 同名 input 保持一致**，否则看板会和真实信号打架。

## 常用接口

| 接口 | 说明 |
|---|---|
| `GET /status` | 系统状态 + 活跃交易/子组/对冲状态 |
| `GET /events?limit=50` | 最近事件（REJECT_*/BEP_HEDGE_ACTIVATED/…） |
| `GET /hedge_stats?days=7` | 对冲统计：日次数/手续费/平均量/MIN_AMOUNT 跳过（规范十八.1） |
| `POST /control/trading?enabled=true|false` | 开关交易 |
| `POST /control/force_close?reason=xxx` | 人工强平（FORCE_CLOSE_MANUAL） |
| `POST /control/close_group?group_id=N` | 独立平掉一个管理子组的买卖两腿 |
| `POST /control/clear_force_close` | 清仓确认后解除强平锁定 |

## 行为口径（已实现）

- 同一时间仅一笔卖方交易；任何来源的期权卖方持仓都会 `REJECT_EXISTING_OPTION_SHORT`；
- 开仓顺序：Combo 组合簿原子成交优先 → 剩余量逐组"买保护腿→卖收权腿"（任何时刻无裸卖），
  卖腿失败自动回滚买腿（`OPEN_FAILED_UNWOUND`）；
- BEP 由后端按实际成交净权利金计算（折算用开仓时指数价）；触及判定用**已收盘 3 分钟 bar 收盘价**；
- 对冲撤销两段式：触线 → `HEDGE_RELEASE_PENDING` → 下一根完整 bar 复核仍在线内侧才归零；
  期间重新突破 BEP 则取消撤销回到 ACTIVE；
- TradingView 传入的 Delta 风险比例、触发比例与 Call/Put 撤销线按父交易保存并实际生效；
- `hedge_state.futures_usd` 只累计本策略真实成交的期货数量；正常退出/对冲撤销只冲销该归属量，
  不会把账户原有人工 BTC-PERPETUAL 仓位误当成本策略对冲归零；
- DVOL 退出双保险：TradingView EXIT 信号与后端自算（120 根已完成 12h bar 的 30 分位）任一触发即平仓；
- DVOL 开仓档位必须取得完整 730 天窗口；样本不足时后端拒绝开仓，不用短窗口代替；
- 每轮扫描按 Deribit mark price 更新子组未实现盈亏与盈利比例；在未定义自动止盈阶梯前，
  监控台支持人工独立平掉子组，不擅自触发未经确认的自动减仓；
- 正常退出默认双腿全平（`exit.keep_buy_leg_on_normal_exit: true` 可切只平卖腿）；
- 强平（RISK/MANUAL 同一函数）：撤全部挂单→平全部期权腿（不留跛腿）→期货归零→
  子组 FORCE_CLOSED；完成后 `force_close_active` 保持置位，需人工 clear；
- 持仓一致性：只核对本系统交易的腿；账户中其他来源的期权仓位只告警+阻止新开仓，不强平。

## 监控台

打开 `http://HOST:8300/`。新版控制台按“系统健康 → 账户风险 → 活跃策略 → 子组 →
真实持仓 → 事件”组织，桌面和手机均可使用。全账户强平必须在专用确认框输入 `YES`；
它会平掉账户全部 BTC 期权与永续仓位，不是单一策略退出。管理页面不要求访问口令；
TradingView webhook 使用独立的 `WEBHOOK_PASSPHRASE` 验证信号来源。

## ⚠ 实盘前必须确认的占位口径（config/base.yaml 中有同样标记）

1. **档位映射** `leg_selection.tier_map`：L1 卖腿|Δ|0.15/DTE30-45；L2 0.20/20-35；L3 0.25/14-28
2. **买腿规则**：盈亏比 ≤ `risk_reward_max`(12) 内选权利金最便宜者（"反向盈亏比"待精确定义）
3. **风险预算** `risk.account_risk_pct`(2%)：每笔最大亏损 ≤ 权益×2%；PUT 深跌压力系数 1.3
4. **风控阈值**：保证金率 60%、日亏 5%、盘口缺失 5 轮、|Delta| 异常 1.0 BTC
5. **Pine 指标参数**：布林带 20/2σ、HV 窗口 20 根 2h、HV 分位窗口 252 根（V1 是 1 分钟体系，
   2 小时版参数需与原回测核对）
6. testnet.yaml 目前为 e2e 验证设了 `account_risk_pct: 0.0005` 和 debug override，
   **正式 testnet 观察运行前应移除**

## 云服务器部署（Linux, systemd）

```ini
# /etc/systemd/system/seller-v2.service
[Unit]
Description=BTC Option Seller V2
After=network-online.target

[Service]
WorkingDirectory=/opt/seller-v2/server
ExecStart=/usr/bin/python3 -m uvicorn src.app:app --host 127.0.0.1 --port 8300
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

HTTPS 反代（Caddy 最简）：`你的域名 { reverse_proxy 127.0.0.1:8300 }`。
崩溃/重启后自动 reconcile：撤孤儿挂单、按交易所实际持仓恢复 OPEN/继续 CLOSING、
跛腿触发 FORCE_CLOSE 等人工。
