# BTC 期权卖方策略 V2 — 运行手册

## 系统组成

```
TradingView Strategy
  ├─ pine/btc_credit_spread_v2_chart.pine（跟随图表周期）
  └─ pine/btc_credit_spread_v2_2h.pine（固定2小时）
    │  唯一策略权威：订单成交 OPEN / CLOSE
    │  webhook: /webhook/signal（通用 JSON V2 + passphrase 鉴权）
    ▼
后端 web/backend/ (Python asyncio + FastAPI, 端口 8300)
    │  接收→校验→去重→入队；不重新计算 DVOL/HV/CCI/布林条件
    │  单 worker 命令队列: 强平 > 平仓 > 对冲撤销 > 对冲调整 > 扫描 > 开仓
    │  3分钟扫描: 持仓核对→风控→BEP→对冲
    │  SQLite: web/backend/data/seller_v2.db
    ▼
Deribit (testnet / mainnet): 期权双腿 + BTC-PERPETUAL 对冲
```

## 本地开发启动

```bash
# 首次安装
python -m pip install -r web/backend/requirements.txt
cd web/frontend
npm install

# 终端一：后端
cd web/backend
python server.py --reload

# 终端二：前端
cd web/frontend
npm run dev
```

开发页面：`http://127.0.0.1:5173`；Vite 自动将 `/status`、`/account`、
`/control/*` 等接口代理到 `http://127.0.0.1:8300`。

连接和测试：

```bash
cd web/backend
python scripts/check_connectivity.py
python -m pytest -q
```

## 单端口运行 / 部署

```bash
cd web/frontend
npm run build               # 构建到 web/backend/static/
cd ../backend
python server.py            # 同时提供 API 和构建后的前端，端口 8300
```

开发时使用 `npm run dev`；部署时不需要长期运行Vite，只需要先构建一次。

`.env` 的 `DERIBIT_ENV=testnet|mainnet` 决定环境；策略参数在 `config/base.yaml`，
环境覆盖在 `config/testnet.yaml` / `config/mainnet.yaml`（mainnet 禁止 debug 旁路）。

首次启动后必须手动开启交易（默认关闭）：
```bash
curl -X POST "http://HOST:8300/control/trading?enabled=true"
```

## TradingView 配置

1. 打开 BTC 图表（建议 `DERIBIT:BTCUSD` 或 BTC-PERPETUAL），周期切到 **3 分钟**；
2. 按需要加载其中一个 Pine v6 文件：
   - `pine/btc_credit_spread_v2_chart.pine`，TradingView 名称
     `BTC期权卖方V2·图表周期版`：开仓条件跟随当前图表；3 分钟图即每根
     已收盘 3 分钟 K 线判断一次；
   - `pine/btc_credit_spread_v2_2h.pine`，TradingView 名称
     `BTC期权卖方V2·固定2小时版`：无论主图周期为何，始终使用已收盘
     2 小时 BTC K 线判断；
   - 两版主图都会标出 `PUT开`、`CALL开` 和 `平仓`，右上角状态表显示实际信号周期；
   - DVOL 档位与退出仍使用已收盘的 12 小时 DVOL 数据，不随图表周期改变；
3. 参数页只配置策略判断参数。`TV 回测虚拟数量` 仅影响 TradingView 回测，
   不决定 Deribit 真实下单数量；真实数量、卖腿 Delta、DTE 和分组由后端风险配置决定；
4. **等图表加载完整历史后**（DVOL 分位需要 730 天 × 2 根 12h bar，需足够的
   TradingView 历史深度，右上角状态表 "DVOL样本" 显示 1460/1460 才达标）；
5. 打开本系统顶部 **TV 接入** 页面：
   - 填写“信号来源名称”，例如 `BTC期权卖方策略 V2`；
   - `source_name` 是后台显示名称；Pine 顶部的 `strategy("…")` 只是
     TradingView 显示标题，两者不要求完全相同；
   - Webhook 口令会从服务器配置自动读取、直接显示并写入 Alert JSON，无需查找 `.env`；
   - 页面会自动生成 `source_id`。同一条 Alert 的开仓和平仓使用同一个 ID；
     每次进入配置新策略页面都会生成新的 ID；
   - 复制 Webhook URL 和 Alert JSON。
6. 在 TradingView 创建 Alert：
   - Condition: 选择对应的 `BTC期权卖方V2·图表周期版` 或
     `BTC期权卖方V2·固定2小时版` → **订单成交**；
   - Webhook URL: 粘贴监控台复制的 `https://你的域名/webhook/signal`；
   - 消息: 粘贴监控台生成的完整 JSON。
7. JSON 中的 `{{strategy.*}}` 占位符必须原样保留。订单成交时 TradingView 会
   替换订单 ID、OPEN/CLOSE 动作和前后仓位；后端再按自己的风险配置选择真实
   Deribit 期权合约并执行。
8. TradingView webhook 只支持 80/443 端口，云服务器需配 HTTPS 反代（Caddy/Nginx）。

> 改过 Pine 脚本、输入参数或 Alert JSON 后，图表上的策略要重新加载，
> **已有 Alert 需要删掉重建**。TradingView 会保存创建 Alert 当时的脚本快照，
> 后续只改图表参数不会自动更新旧 Alert。

## 开仓条件实时看板

策略判定始终以 TradingView 为准。系统在没有订单成交事件时不会收到消息，
静默期是正常状态；策略首次显示在“策略信号”页面，通常发生在收到第一条真实
开仓或退出信号后。后端可以展示 Deribit 行情诊断，但不会用自己的 DVOL、HV、
CCI 或布林结果二次批准或否决 TradingView 信号。TradingView 的 DVOL 历史不足时，
`tier=-1` 会在 Pine 内直接阻止开仓。

`config/base.yaml` 的 `entry_signal` 和后端拉取的 Deribit DVOL 目前只服务于
只读诊断面板，不是开仓门槛。后端不得用自己的 DVOL、HV、CCI 或布林结果
批准、拒绝或补发 V2 信号；样本不足必须由 Pine 失败关闭。主图状态表中
`DVOL数据` 必须显示 `就绪 1460/1460`，否则 Pine 显示具体原因并停止开仓。

### 指标输入源（易错）

规范第五节只写了 `abs(CCI20) < 101`，没写用什么价格。三个指标的源并不相同：

| 指标 | 输入源 | 说明 |
|---|---|---|
| 布林带上下轨 | 收盘价 close | 标准布林带 |
| HV 及其分位 | 收盘价 close 的对数收益率 | |
| **CCI** | **典型价 hlc3** | 未加限定词的 CCI 即标准指标，Lambert 原始定义用典型价 |

CCI 用错源不会报错，只会算出另一个数：2026-07-22 同一批数据 close 口径
135.2、hlc3 口径 163.4，**在阈值 101 附近会一个放行一个拦截**。Pine 与后端
两侧必须同时改，否则看板显示的和真实信号判定会不一致。

## 常用接口

| 接口 | 说明 |
|---|---|
| `GET /status` | 系统状态 + 活跃交易/子组/对冲状态 |
| `GET /events?limit=50` | 最近事件（REJECT_*/BEP_HEDGE_ACTIVATED/…） |
| `GET /hedge_stats?days=7` | 对冲统计：日次数/手续费/平均量/MIN_AMOUNT 跳过（规范十八.1） |
| `GET /api/tradingview_setup` | 实验阶段返回 Alert 设置元数据及 Webhook 口令 |
| `POST /webhook/signal` | TradingView 标准信号入口 |
| `POST /webhook/tradingview` | 旧入口，兼容已有 Alert |
| `POST /control/trading?enabled=true|false` | 开关交易 |
| `POST /control/force_close?reason=xxx` | 人工强平（FORCE_CLOSE_MANUAL） |
| `POST /control/close_group?group_id=N` | 独立平掉一个管理子组的买卖两腿 |
| `POST /control/clear_force_close` | 清仓确认后解除强平锁定 |

## 行为口径（已实现）

- 后端同一时间只允许一个信号源占用交易账户；该来源可按 TradingView 的每条
  OPEN 信号独立建立多笔 `PUT_CREDIT` / `CALL_CREDIT`。其他来源会
  `REJECT_OTHER_SIGNAL_SOURCE`，账户外卖方仓位仍会 `REJECT_EXISTING_OPTION_SHORT`；
- 每条 OPEN 受单笔 `risk.account_risk_pct` 算量限制；所有活跃批次还共享
  `risk.portfolio_risk_pct` 组合风险额度。新批次按两者剩余额度中的较小值缩量，
  额度不足最小下单单位时以 `REJECT_PORTFOLIO_RISK_LIMIT` 拒绝；子组部分平仓会按
  剩余数量释放额度；
- 同源加仓要求已有批次处于稳定持仓状态；存在未完成的 OPENING/CLOSING 时以
  `REJECT_SIGNAL_SOURCE_BUSY` 拒绝，等待执行链收敛后再接受后续信号；
- 开仓顺序：Combo 组合簿原子成交优先 → 剩余量逐组"买保护腿→卖收权腿"（任何时刻无裸卖），
  卖腿失败自动回滚买腿（`OPEN_FAILED_UNWOUND`）；
- BEP 由后端按实际成交净权利金计算（折算用开仓时指数价）；对冲提前激活价为
  `开仓指数价 + (BEP - 开仓指数价) × bep_activation_progress`，默认进度 20%；触及判定使用 Deribit
  `deribit_price_index.btc_usd` 的**实时 BTC 指数价**，3 分钟扫描保留为断线兜底；
- 对冲撤销两段式：触线 → `HEDGE_RELEASE_PENDING` → 下一根完整 bar 复核仍在线内侧才归零；
  撤销线以提前激活价为基准，期间重新突破提前激活价则取消撤销回到 ACTIVE；
- 通用 V2 信号只传来源、订单动作与仓位变化；卖腿 Delta、DTE、真实数量、
  分组和对冲参数统一使用后端配置；
- `hedge_state.futures_usd` 只累计本策略真实成交的期货数量；正常退出/对冲撤销只冲销该归属量，
  不会把账户原有人工 BTC-PERPETUAL 仓位误当成本策略对冲归零；
- DVOL 开仓和退出都由 TradingView Strategy 决定；后端不再运行第二套 DVOL 自动退出；
- CALL/PUT 开仓彼此独立；方向切换只产生另一侧 OPEN，不再隐式平掉已有价差；
- CLOSE 优先按 `source_id + spread_type` 关闭对应方向的全部批次，并兼容旧 Alert
  的 `tv_id/trade_id`；
  两者都缺少时，仅在当前恰好只有一笔开放交易的情况下兼容，不会“一条信号平全部”；
- 同一 `signal_id` 只处理一次；Webhook 收到后立即入队并返回 202，避免
  TradingView 超时重试造成重复订单；
- 每轮扫描按 Deribit mark price 更新子组未实现盈亏与盈利比例；在未定义自动止盈阶梯前，
  监控台支持人工独立平掉子组，不擅自触发未经确认的自动减仓；
- 正常退出默认双腿全平（`exit.keep_buy_leg_on_normal_exit: true` 可切只平卖腿）；
- 强平（RISK/MANUAL 同一函数）：撤全部挂单→平全部期权腿（不留跛腿）→期货归零→
  子组 FORCE_CLOSED；完成后 `force_close_active` 保持置位，需人工 clear；
- 持仓一致性：只核对本系统交易的腿；账户中其他来源的期权仓位只告警+阻止新开仓，不强平。

## 监控台

打开 `http://HOST:8300/`。新版控制台按“系统健康 → 账户风险 → 活跃策略 → 子组 →
真实持仓 → 事件”组织，桌面和手机均可使用。全账户强平需要在专用确认框确认；
它会平掉账户全部 BTC 期权与永续仓位，不是单一策略退出。管理页面不要求访问口令；
TradingView webhook 使用独立的 `WEBHOOK_PASSPHRASE` 验证信号来源。

## ⚠ 实盘前必须确认的占位口径（config/base.yaml 中有同样标记）

1. **档位映射** `leg_selection.tier_map`：L1 卖腿|Δ|0.15/DTE30-45；L2 0.20/20-35；L3 0.25/14-28
2. **买腿规则**：在满足净收权利金的候选中选择权利金最便宜者；实际盈亏比仅记录诊断，不作为准入限制
3. **风险预算**：单笔 `risk.account_risk_pct`(2%)；组合
   `risk.portfolio_risk_pct`(6%)；PUT 深跌压力系数 1.3
4. **风控阈值**：保证金率 60%、日亏 5%、盘口缺失 5 轮、|Delta| 异常 1.0 BTC
5. **Pine 指标参数**：布林带 20/2σ、HV 窗口 20 根图表 bar、HV 分位窗口
   252 根图表 bar；切换图表周期会改变这些窗口对应的实际时间跨度，需要重新回测确认
6. Testnet 与 Mainnet 都继承上述风险预算；环境覆盖文件不得放宽 Mainnet 风控。

## 云服务器部署（Linux, systemd）

```ini
# /etc/systemd/system/seller-v2.service
[Unit]
Description=BTC Option Seller V2
After=network-online.target

[Service]
WorkingDirectory=/opt/seller-v2/server
ExecStart=/usr/bin/python3 -m uvicorn src.app:app --host 127.0.0.1 --port 8300
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

HTTPS 反代（Caddy 最简）：`你的域名 { reverse_proxy 127.0.0.1:8300 }`。
崩溃/重启后自动 reconcile：撤孤儿挂单、按交易所实际持仓恢复 OPEN/继续 CLOSING、
跛腿触发 FORCE_CLOSE 等人工。
