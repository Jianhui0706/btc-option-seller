# Beginner-Friendly Signal Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the active-signals page’s technical two-stage presentation with a beginner-friendly four-step journey that states whether opening is possible, where the process has stopped, and why.

**Architecture:** Keep the existing backend APIs and trading logic unchanged. Add pure frontend view-model helpers that combine Pine conditions, the matching real `OPEN_REQUEST`, backend processing status, and the matching parent trade into one authoritative journey state; render that state as a four-step accessible accordion with a single natural-language headline.

**Tech Stack:** Single-file HTML/CSS/JavaScript frontend, Node built-in test runner, Vite, existing FastAPI JSON endpoints, pytest, PowerShell deployment scripts.

## Global Constraints

- Do not modify Pine signal-generation behavior, DVOL/HV/CCI thresholds, backend acceptance rules, order execution, or risk controls.
- The first screen must answer within 3 seconds: whether opening is possible, the current step, and the main reason.
- Use exactly four steps: `等待市场出现开仓机会`, `TradingView 发送开仓申请`, `系统进行最终安全检查`, `允许并执行开仓`.
- Use exactly five headline states: `现在不能开仓`, `等待开仓申请`, `系统正在检查`, `正在执行开仓`, `已经开仓`.
- Only a real `OPEN_REQUEST`/`OPEN_SIGNAL` counts as an opening request; STATUS/connection reports never pass Step 2.
- Backend preflight is blue informational copy and never counts as a real rejection.
- A matching signal’s actual status and `reject_reason` override preflight.
- Data from different 2-hour bars must not be combined into one journey instance.
- `dvol_tier=-1` is blue `交后端判断`; it does not block TradingView when the other Pine conditions pass.
- Waiting for PUT/CALL Bollinger shape is amber, not an error.
- Current step is open by default; every step remains manually expandable and collapsible.
- No expanded detail may expose Webhook passphrases, API keys, authorization headers, or other secrets.
- Preserve the current dark visual system and the four-tab page structure.
- Desktop and mobile use the same vertical step order with no page-level horizontal scrolling.
- The cloud package remains locked to Deribit TESTNET.
- Existing unrelated working-tree changes under `web/backend/` are user-owned and must not be staged, reverted, or overwritten.

- `web/frontend/index.html`

- [ ] **Step 6: Implement exact matching helpers**

Add these helpers immediately after `buildTradingViewStage`:

```js
function matchOpenSignal(conditions,signals){
  const barTs=Number(conditions?.pine?.bar_ts);
  if(!Number.isFinite(barTs))return null;
  const expectedStrategy=String(conditions?.pine?.strategy||"");
  const expectedSide=conditions?.pine?.put_shape===true
    ?"PUT_CREDIT"
    :conditions?.pine?.call_shape===true
      ?"CALL_CREDIT"
      :"";
  return (signals?.items||[])
    .filter(item=>item?.kind==="OPEN_SIGNAL"&&item?.event==="OPEN_REQUEST")
    .filter(item=>{
      const payloadBar=Number(item?.payload?.bar_ts);
      const suffix=String(item?.signal_id||"").match(/_(\d{10,13})$/);
      const signalBar=Number.isFinite(payloadBar)&&payloadBar>0
        ?payloadBar
        :Number(suffix?.[1]);
      const strategyOk=!expectedStrategy||!item?.strategy||item.strategy===expectedStrategy;
      const sideOk=!expectedSide||item?.spread_type===expectedSide;
      return signalBar===barTs&&strategyOk&&sideOk;
    })
    .sort((a,b)=>Number(b.received_at||0)-Number(a.received_at||0))[0]||null;
}

function matchSignalTrade(signal,trades){
  if(!signal?.signal_id)return null;
  return (trades||[])
    .filter(trade=>String(trade?.signal_id||"")===String(signal.signal_id))
    .sort((a,b)=>Number(b.id||0)-Number(a.id||0))[0]||null;
}
```

The current Pine opening payload puts the 2-hour timestamp at the exact numeric suffix of `signal_id`; it does not always include `payload.bar_ts`. Accept either an explicit equal `payload.bar_ts` or that exact suffix. Do not use nearby time or arbitrary substring matching.

function buildExecutionStage(signalStage,trades){
  if(!signalStage.actual||signalStage.state!=="accepted")
    return {state:"not_started",trade:null,title:"尚未开始",reason:"等待前序步骤通过"};
  const trade=matchSignalTrade(signalStage.signal,trades);
  if(!trade)return {state:"starting",trade:null,title:"准备执行开仓",reason:"信号已接受，等待建立交易记录"};
  const states={
    SIGNAL_RECEIVED:["starting","准备执行开仓"],
    POSITION_CHECKING:["checking","检查现有仓位"],
    SELECTING_LEGS:["selecting","选择期权合约"],
    OPENING:["opening","订单正在执行"],
    OPEN:["open","开仓成功"],
    OPEN_FAILED:["failed","执行失败"],
  };
  const [state,title]=states[trade.state]||["starting","正在执行开仓"];
  return {state,trade,title,reason:trade.close_reason||null};
}

Replace `buildBackendStage` and add the complete journey reducer:

```js
function buildBackendStage(data,signals){
  const matched=matchOpenSignal(data,signals);
  if(matched){
    const status=String(matched.status||"").toUpperCase();
    const state=status==="ACCEPTED"
      ?"accepted"
      :status==="REJECTED"
        ?"rejected"
        :"processing";
    return {
      state,actual:true,status,
      reason:matched.reject_reason||null,
      signal:matched,
      dvol:data?.backend?.checks?.dvol_tier||null,
    };
  }
  const check=data?.backend?.checks?.dvol_tier;
  return {
    state:"waiting",actual:false,
    preflight:!check||check.ok==null?"unknown":check.ok?"allow":"reject",
    dvol:check||null,
  };
}

function tradingViewPrimaryReason(data,tv){
  const p=data?.pine;
  if(!p)return "尚未收到 TradingView 状态";
  if(tv.state==="unknown"){
    const age=Number(data?.server_ts||Date.now())-Number(p.received_at||0);
    return age>150*60*1000
      ?"TradingView 状态已过期，暂时无法判断"
      :"TradingView 数据不足，暂时无法判断";
  }
  if(p.cfg_ok===false)return "档位配置不符合 L1 < L2 < L3";
  if(p.dvol_tier>=0&&p.tier_ok===false)return "TradingView DVOL 档位低于开仓要求";
  if(p.hv_ok===false){
    const value=p.hv_percentile==null?"—":`${(Number(p.hv_percentile)*100).toFixed(1)}%`;
    const threshold=Number(p?.params?.hv_pctl_min??data?.backend?.checks?.hv?.threshold??30);
    return `HV 分位 ${value}，低于 ${threshold.toFixed(0)}% 要求`;
  }
  if(p.cci_ok===false){
    const value=p.cci==null?"—":Number(p.cci).toFixed(1);
    const threshold=Number(p?.params?.cci_max??data?.backend?.checks?.cci?.threshold??101);
    return `CCI ${value}，未满足 |CCI| < ${threshold.toFixed(0)}`;
  }
  if(tv.state==="waiting")return "PUT/CALL 布林形态尚未触发";
  return "TradingView 条件已满足，等待开仓申请到达";
}

function buildSignalJourney(data,signals,trades){
  const tv=buildTradingViewStage(data);
  const backend=buildBackendStage(data,signals);
  const execution=buildExecutionStage(backend,trades);
  const wd=data?.watchdog||{};
  const sameWatchdogBar=Number(wd.bar_ts)===Number(data?.pine?.bar_ts);
  const timedOut=!backend.actual&&sameWatchdogBar&&wd.armed===true&&wd.alarm===true;
  const delivery=backend.actual
    ?{
      state:"received",tone:"pass",signal:backend.signal,
      title:"已收到开仓申请",
      reason:`${backend.signal.spread_type==="PUT_CREDIT"?"PUT":"CALL"} 开仓申请已到达`,
    }
    :timedOut
      ?{
        state:"timeout",tone:"timeout",signal:null,
        title:"开仓申请到达超时",
        reason:"TradingView 应已发出申请，但系统尚未收到",
      }
      :tv.state==="ready_to_send"
        ?{
          state:"waiting",tone:"wait",signal:null,
          title:"等待开仓申请",
          reason:"TradingView 已具备发信条件，等待 Webhook 到达",
        }
        :{
          state:"not_expected",tone:"idle",signal:null,
          title:"尚不应发信",
          reason:"市场条件还没有全部满足",
        };
  const safety=backend.actual
    ?{
      ...backend,mode:"actual",
      tone:backend.state==="accepted"
        ?"pass"
        :backend.state==="rejected"
          ?"block"
          :"processing",
    }
    :{
      ...backend,state:"preflight",mode:"preflight",tone:"info",
      title:"提前预警，不是实际拒绝",
    };

  let currentStep,state,headline,reason;
  if(backend.actual&&backend.state==="accepted"){
    currentStep=4;
    if(execution.state==="open"){
      state="opened";
      headline="已经开仓";
      reason="期权价差已经开仓";
    }else if(execution.state==="failed"){
      state="blocked";
      headline="现在不能开仓";
      reason=execution.reason||"开仓执行失败";
    }else{
      state="executing";
      headline="正在执行开仓";
      reason=execution.title;
    }
  }else if(backend.actual){
    currentStep=3;
    if(backend.state==="rejected"){
      state="blocked";
      headline="现在不能开仓";
      reason=backend.reason||"系统拒绝本次开仓申请";
    }else{
      state="checking";
      headline="系统正在检查";
      reason="系统正在进行最终安全检查";
    }
  }else if(tv.state==="ready_to_send"){
    currentStep=2;
    state="waiting_signal";
    headline="等待开仓申请";
    reason=delivery.reason;
  }else{
    currentStep=1;
    state="blocked";
    headline="现在不能开仓";
    reason=tradingViewPrimaryReason(data,tv);
  }

  return {
    instanceKey:backend.signal?.signal_id
      ?`signal:${backend.signal.signal_id}`
      :data?.pine?.bar_ts
        ?`pine:${data.pine.bar_ts}`
        :"pine:missing",
    currentStep,state,headline,reason,
    tv,delivery,safety,execution,
  };
}
```

Keep raw rejection codes in the pure model. Map them through `REJECT_REASON` only during rendering.

- [ ] **Step 5: Implement persistent-per-instance expansion**

Add state and interaction helpers near the existing condition accordion state:

```js
const journeyStepOverrides={};
let journeyInstanceKey=null;
let journeyAutoStep=null;

function syncJourneyExpansion(journey){
  if(journey.instanceKey!==journeyInstanceKey){
    for(const key of Object.keys(journeyStepOverrides))delete journeyStepOverrides[key];
    journeyInstanceKey=journey.instanceKey;
    journeyAutoStep=null;
  }
  if(journey.currentStep!==journeyAutoStep){
    journeyStepOverrides[journey.currentStep]=true;
    journeyAutoStep=journey.currentStep;
  }
}

function toggleJourneyStep(step){
  const el=$(`journeyStep${step}`);
  const open=el?.querySelector(".journey-step-toggle")?.getAttribute("aria-expanded")==="true";
  journeyStepOverrides[step]=!open;
  if(model?.conditions)renderConditions(model.conditions,model.signals,model.trades);
}
```

For a step without an override, `renderJourneyStep` uses `step===journey.currentStep`. This lets users close the current step or open additional steps until a new journey instance or current-step transition occurs.
