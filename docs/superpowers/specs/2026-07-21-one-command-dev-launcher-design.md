# 前后端一键启动器设计

## 目标

用户在项目根目录终端输入一条命令：

```powershell
.\start.ps1
```

脚本自动安全重启 VolGuard testnet 后端和 Vite 前端。只有前后端都通过健康检查后，脚本才打开浏览器。

## 启动流程

1. 解析项目根目录、`web/backend` 和 `web/frontend` 的绝对路径。
2. 检查 Python、Node.js 和 npm 是否可用。
3. 查找本项目此前启动的前后端进程并停止它们。
4. 等待后端端口 `8300` 和前端端口 `5173` 释放。
5. 如果端口仍被非本项目进程占用，中止启动并提示占用进程，不进行误杀。
6. 从 `web/backend` 使用 `python server.py` 启动后端，不启用 `--reload`。
7. 从 `web/frontend` 使用 `npm run dev -- --host 127.0.0.1 --port 5173 --strictPort` 启动前端。
8. 后端轮询 `http://127.0.0.1:8300/status`；前端轮询 `http://127.0.0.1:5173/`。
9. 两个检查均成功后打开前端地址，并在当前控制台显示 PID、testnet 环境和活动交易数量。

## 进程和日志

- 前后端作为隐藏子进程运行，当前 PowerShell 控制台负责报告启动结果。
- 标准输出和错误输出分别保存到 `web/backend/logs` 和 `web/frontend/logs`。
- 脚本保存本次启动的 PID，下一次运行时优先按 PID 和命令路径识别本项目进程。
- 启动失败时，停止本次已经启动的子进程，并显示对应错误日志的末尾内容。

## 安全边界

- 只停止能够确认属于当前项目目录的进程。
- 同端口的未知进程不会被自动终止。
- 后端必须返回有效 `/status`，前端必须返回 HTTP 成功状态，才视为启动完成。
- 默认打开浏览器；可用 `-NoBrowser` 参数跳过浏览器，便于自动验证。

## 验证

- 静态检查 PowerShell 语法。
- 在旧服务运行时执行脚本，确认旧 PID 被替换。
- 验证端口 `8300` 和 `5173` 可访问。
- 验证 `/status` 保持 `env=testnet`，且已有活动交易未丢失。
- 验证 `-NoBrowser` 模式可用于无交互测试。
