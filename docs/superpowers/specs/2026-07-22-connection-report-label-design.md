# 信号中心“连接回报”文案与合并指标设计

## 目标

将信号中心所有面向用户的“心跳”术语统一替换为“连接回报”，并在现有指标卡中同时显示开仓信号数量与 Webhook 接收总数，不增加第七张卡。

## 指标规则

- 原“真实信号总数”卡片改为“开仓信号 / 收到信号”。
- 主数值使用 `open_signals / total`，例如 `0 / 1`。
- `open_signals` 只统计 TradingView 的 `OPEN_REQUEST`。
- `total` 是当前活动窗口内的 Webhook 接收总数，包含连接回报、开仓信号和退出信号。
- 卡片说明固定提示“收到信号包含连接回报”，避免将连接回报理解为可开仓信号。
- 保持现有六张指标卡布局不变。

## 文案规则

- 活动记录类型“链路心跳”改为“连接回报”。
- 活动面板说明“蓝色是链路心跳”改为“蓝色是连接回报”。
- 顶部统计由“心跳”改为“回报”，例如 `1 回报 · 0 信号`。
- 空状态、等待状态、连接状态以及开仓条件面板中所有用户可见的“Pine 心跳”统一改为“Pine 连接回报”。
- 内部 API 字段 `kind=HEARTBEAT`、汇总键 `heartbeats`、数据库表名和 Python/JavaScript 内部变量保持不变。

## 行为边界

- 只修改显示与指标计算，不改变 TradingView 信号判断、Webhook 鉴权、开仓队列或风控逻辑。
- 连接回报仍只证明链路正常，绝不触发开仓。

## 验证与部署

- 前端契约测试验证新术语、比例公式和旧术语不再出现在用户文案中。
- 运行完整前端测试、生产构建、后端回归和启动测试。
- 部署至现有 testnet 云端，验证公网信号中心显示新指标和新文案。
