# 深色四栏交易仪表板设计

## 目标

参考老师提供的 `dashboard.html` 信息结构，把现有“总览、信号中心、收益分析”三个页面重构为老师熟悉的四栏操作路径，同时保留现有深色专业交易风格、全部业务功能和安全控制。

四栏名称严格为：

1. 仓位
2. 活跃信号
3. 信号日志
4. 仓位日志

## 设计原则

- 老师是主要使用者，栏目名称和操作路径优先与参考页面一致。
- 借鉴参考页面的标题区、横向指标卡、标签导航和单一主内容容器，不复制其紫色渐变和亮色外观。
- 顶部区域适当留白，详细记录区域保持紧凑，实现“易读”与“一屏多看”之间的折中。
- 不删除、不伪造、不简化业务数据；只重新组织视觉层和信息层级。
- 不修改 API、Pine、开仓条件、风险控制、订单执行或数据库语义。

## 全局框架

### 系统栏

顶部保留品牌、TESTNET 标识、策略引擎状态、最近扫描时间。右侧保留手动刷新、暂停开仓和全账户强平。

### 页面标题区

显示“BTC 期权卖方交易仪表板”、运行环境、简短说明与 TradingView 链路状态。视觉采用深色大卡片，布局参考老师页面的白色标题卡。

### 核心指标区

四栏上方固定显示五张指标卡，切换栏目时不消失：

- 账户权益
- 可用保证金
- 当前持仓
- 开仓信号 / 收到信号
- 今日盈亏

系统风险异常通过标题区的状态提示和红色警告条展示，不挤占常驻指标卡。

### 四栏导航

横向标签顺序固定为“仓位、活跃信号、信号日志、仓位日志”。当前栏使用青绿色高亮，其他栏保持低对比深色。导航支持浏览器前进、后退和直接 URL 访问。

### 主内容容器

每栏以一个主要深色面板承载核心数据，必要时使用一个辅助面板。减少小面板层层嵌套；记录与明细采用紧凑表格或可展开行。

## 栏目设计

### 1. 仓位

用途：查看和管理当前 Deribit 策略持仓。

- 父策略摘要：信用价差方向、状态、剩余数量、净权利金、盈亏平衡点和未实现盈亏。
- 展开明细：买卖腿、到期日、行权价、四个管理子组、各组盈亏与状态。
- 操作：单组平仓；全账户强平仍位于全局顶部。
- 无持仓时显示明确空状态，并说明系统仍在监听 TradingView 信号。
- 原总览页的“活跃策略”和“持仓管理”全部迁入本栏。

### 2. 活跃信号

用途：判断当前是否具备开仓条件，并观察正在等待或处理的真实信号。

- 开仓条件实时看板作为主内容：配置、DVOL 档位、HV 分位、CCI 和布林形态。
- 每项默认只显示当前值、标准和通过结论；距离阈值、方向形态和原始计算可展开。
- 显示实时 BTC 价格、距离上下轨、TradingView 数据时间和后端权威 DVOL 结论。
- 显示处理中或最近仍具有执行意义的开仓信号；连接回报不进入活跃开仓信号列表。
- 条件满足但未收到 TradingView 开仓推送时，保留醒目的推送看门狗警告。

### 3. 信号日志

用途：审计 TradingView 到系统的全部链路活动。

- 统一展示连接回报、开仓信号和退出信号。
- 蓝色：连接回报；绿色：已接受的真实开仓信号；青色：已接受的退出信号；红色：系统拒绝；黄色：处理中。
- 每条记录默认显示类型、策略或信号 ID、接收时间和处理结论。
- 点击展开完整参数；拒绝记录必须显示明确拒绝理由。
- 统计口径继续为“开仓信号数量 / 收到信号数量”，收到信号包含去重后的连接回报。
- Webhook 地址和复制操作放在本栏辅助面板，不占用主日志空间。

### 4. 仓位日志

用途：查看已执行策略的历史、收益和系统执行过程。

- 顶部展示累计净收益、已实现、未实现、今日收益和胜率。
- 30 日收益图作为主要视觉区。
- 历史交易表显示策略编号、信号、方向、状态、开仓时间、平仓时间和盈亏。
- 点击交易行展开手续费、对冲动作、子组结果和关闭原因。
- 原总览页事件流迁入本栏的“执行记录”子区，可按 INFO、WARN、ERROR 筛选。
- 原收益分析页全部迁入本栏。

## 交互规范

- 页面每 5 秒自动刷新，保留手动刷新按钮。
- 下拉明细同一列表默认只展开一项，避免页面拥挤。
- 桌面端详细历史使用宽表格；窄屏切换为纵向卡片，不强迫用户横向滚动。
- 表格表头、数值列、状态标签与参考页保持清晰对齐，但使用现有深色设计令牌。
- 所有空状态、加载状态和接口错误都在对应主面板内展示，不让整页布局跳动。

## 安全规范

- 暂停开仓与全账户强平始终可见。
- 强平继续使用红色危险按钮和二次确认，不因视觉重构弱化。
- 连接回报不得显示为绿色，也不得进入开仓信号数量。
- 只有真实开仓信号可以使用绿色交易语义。
- 拒绝记录标红且可展开查看拒绝理由。
- Webhook passphrase、密钥和其他敏感字段在渲染前过滤并进行 HTML 转义。
- 本次重构不改变任何交易控制接口的调用条件。

## 路由与兼容

- `/` 对应“仓位”。
- `/signals` 对应“活跃信号”。
- 新增 `/signal-log` 对应“信号日志”。
- `/returns` 对应“仓位日志”，保留旧收益分析链接兼容性。
- 浏览器历史、页面标题、移动端菜单与四栏状态保持同步。

## 响应式设计

- 大屏：五张指标卡横排，四栏导航横排，主数据使用表格。
- 中屏：指标卡自动换行，导航仍保持四栏等宽。
- 手机：指标卡两列；四栏导航允许等宽紧凑排布；表格切换为卡片；危险操作收进明确的操作菜单，但强平入口仍可找到。

## 测试与验收

- 自动测试验证四栏名称、顺序、路由和活动状态。
- 自动测试验证旧页面的所有核心 DOM 与数据渲染职责已迁移而未丢失。
- 自动测试验证连接回报、开仓信号、拒绝信号的颜色和计数语义不变。
- 自动测试验证强平确认、暂停开仓和敏感字段过滤仍有效。
- 后端完整测试通过，证明接口和交易逻辑未被视觉重构破坏。
- Vite 构建成功，桌面和手机宽度进行截图核对。
- 云端部署后逐栏核对真实数据、TESTNET 标识、交易开关和 HTTPS 状态。

## 不在本次范围

- 不引入新的前端框架或图表依赖。
- 不增加老师参考页面中的“生成信号模板”功能。
- 不改变 TradingView Webhook、Pine 或 Deribit 交易行为。
- 不为了填满页面制造不存在的指标或交易记录。
