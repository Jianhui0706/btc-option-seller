# 活跃信号页“阻断原因优先”改版设计

## 目标

让用户打开“活跃信号”页面后，第一眼就能回答：

1. 当前能否发出开仓信号；
2. 如果不能，被哪些条件阻断；
3. 每个阻断条件距离门槛还差多少；
4. 当前判断来自 TradingView 还是后端降级数据。

本次只重构前端信息架构、视觉层级和折叠交互，不修改 Pine、后端条件计算、信号接收或开仓规则。

## 阅读顺序

页面采用固定的自上而下阅读路径：

1. 当前结论；
2. 需要先解决的阻断项；
3. 已通过条件；
4. 最终布林触发形态；
5. 待处理与最近真实信号。

## 页面组成

### 1. 当前结论卡

结论卡位于条件面板最上方，承担整个页面的主要判断。

- 阻断状态：琥珀色或红色，显示“现在不会发出开仓信号”和阻断项数量；正文直接列出阻断条件。
- 等待形态：琥珀色，显示“前置门槛已通过，等待布林触发形态”。
- 全部满足：绿色，显示“最近一根 2h K 线满足全部条件”，并提示核对下方真实信号。
- 数据不足：中性灰或告警色，显示“暂时无法判定”，明确缺失或过期的数据来源。

结论卡同时显示判断依据和最后更新时间，但它们作为次级信息，不与主要结论争夺视觉注意力。

### 2. 阻断项卡片区

仅包含当前明确判定为未通过的前置条件。阻断项按照策略门槛的固定顺序排列，页面刷新后不因差距大小变化而跳动。

每张卡片默认展开，并包含：

- 条件名称；
- 当前值；
- 门槛值；
- 与门槛的差距；
- 简短的人话解释；
- 权威来源（TradingView、后端 DVOL 权威判定或后端降级）；
- 可理解的进度或差距条。

差距必须使用明确方向，例如“距离 40% 还差 32.7pt”，避免只展示红色数值而让用户自行计算。

### 3. 已通过条件折叠区

已通过的前置条件默认收起，标题显示“已通过 N 项”。点击标题后展开全部通过项，再次点击收起。

展开后的每项显示当前值、标准、来源和“通过”状态。折叠状态只保存在当前页面会话中，不写入后端，也不改变策略状态。

### 4. 布林触发形态区

布林形态是最终触发步骤，与 DVOL、HV 和 CCI 等前置门槛分区展示。

- 存在前置阻断时：显示“等待前置门槛”，PUT/CALL 细节默认收起但可以展开。
- 前置门槛全部通过但形态未成立时：突出显示“等待破轨 + 反向收线”，PUT/CALL 方向卡片展开。
- 形态成立时：对应方向以绿色突出，显示触发方向和判断细节。
- 数据缺失时：显示“暂时无法判定”，不错误标红为未通过。

### 5. 实时行情与技术信息

BTC 实时价格、距上下轨距离、数据更新时间和 Pine/后端口径说明保留，但降低视觉权重。

- 实时价格放入结论卡下方的紧凑信息条；
- Pine 推送看门狗异常仍使用醒目的独立警告；
- 计算时间、K 线时间和口径差异放入“数据与判断依据”折叠区；
- 不在每个条件中重复相同的连接回报说明。

### 6. 待处理与最近真实信号

该区域保留在条件看板下方，与条件判断形成明显分区。它仍只展示真实开仓信号；连接回报继续在“信号日志”中查看。

## 数据与判定规则

现有 `entry_conditions` 数据结构和权威来源规则保持不变：

- Pine 连接回报新鲜时，配置、HV、CCI 和布林形态以 TradingView 为准；
- Pine 主动把 DVOL 档位交给后端判定时，DVOL 使用后端权威结论；
- Pine 连接回报过期时，页面明确标记“后端降级数据”；
- `false` 表示阻断，`true` 表示通过，`null` 表示暂时无法判定；
- `null` 不得归类为阻断或通过。

页面从现有五项条件生成三个集合：阻断项、通过项和待定项。布林形态作为最终触发步骤单独渲染，不混入通过项折叠区。

## 交互规则

- 阻断项始终展开；
- 已通过条件默认收起，用户可展开；
- 布林形态根据前置门槛状态决定默认展开程度；
- 页面自动刷新时保留本次页面会话中的折叠状态；
- 任何折叠操作只影响展示，不发起交易请求；
- 手机端使用单列卡片，数值、差距和状态不依赖横向表格阅读。

## 响应式设计

- 桌面端：阻断卡可使用两列布局；单个阻断项时占满可用宽度。
- 窄屏和平板：阻断卡改为单列，结论与更新时间允许换行。
- 手机端：条件名称、当前值和差距按垂直顺序排列，差距条占满卡片宽度；折叠标题保留足够点击区域。
- 页面不得产生横向滚动；现有吸顶四栏导航和移动安全菜单不受影响。

## 异常与空状态

- 后端接口不可用：沿用全局连接异常提示，条件区保留最后一次成功数据时不得伪装成实时结果。
- Pine 数据缺失或过期：结论卡明确显示数据来源变化。
- 后端数据也不可用：显示“暂时无法判定”，并列出缺失项。
- 没有阻断项：隐藏“需要先解决”区域，不展示空框。
- 没有通过项：隐藏“已通过 N 项”折叠区。
- 没有真实开仓信号：保留现有等待 TradingView 信号的空状态。

## 测试与验收

### 自动化测试

- 阻断项被放入独立、默认展开的卡片区；
- 阻断卡展示当前值、门槛、差距和来源；
- 已通过项默认折叠且能够展开；
- 待定状态不会被归为未通过；
- 全部前置门槛通过时切换为等待布林形态；
- 布林形态满足时显示绿色完成状态；
- Pine 过期时明确显示后端降级来源；
- 手机端相关样式存在且不破坏四栏导航与安全操作入口。

### 浏览器验收

使用真实接口数据检查桌面、窄屏和手机三种宽度：

- 第一屏能够直接看到不能开仓的主要原因；
- 未通过项无需点击即可读懂；
- 已通过项能够展开和收起；
- 页面无横向溢出；
- 自动刷新后折叠状态保持；
- 四栏导航及移动端安全菜单仍可正常使用。
