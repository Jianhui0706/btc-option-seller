# 活跃信号两阶段判定设计

## 目标

活跃信号页必须分别回答两个问题：

1. TradingView 当前为什么发送或没有发送 `OPEN_REQUEST`？
2. 后端收到 `OPEN_REQUEST` 后，会允许开仓还是拒绝执行？

页面不得把后端预检结果描述成 TradingView 的发信条件，也不得让用户误以为只满足 DVOL 就能开仓。

## 核心语义

### 第一阶段：TradingView 信号生成

第一阶段只使用 Pine 连接回报中的状态，按固定顺序展示：

| 条件 | 当前值 | 开仓要求 | 状态语义 |
| --- | --- | --- | --- |
| 档位配置 | L1、L2、L3 | `L1 < L2 < L3` | 通过 / 阻断 / 待定 |
| DVOL 判定方式 | Pine 样本数、`dvol_tier` | 样本足够时按 Pine 档位；`tier=-1` 时交后端 | 通过 / 阻断 / **交后端判断** / 待定 |
| HV 分位 | Pine 当前 HV 分位 | `HV >= 下限` | 通过 / 阻断 / 待定 |
| CCI | Pine 当前 CCI | `abs(CCI) < 上限` | 通过 / 阻断 / 待定 |
| PUT/CALL 布林触发 | 当前 K 线、上下轨、阴阳线 | 破轨且反向收线 | 已触发 / 等待触发 / 待定 |

`tier=-1` 必须显示为蓝色中性状态“交后端判断”，不能计入“已通过”，也不能显示为“阻断”。Pine 代码中的 `tier_ok=true` 表示样本不足不会阻止其在其他条件满足时发送信号。

第一阶段结论必须由 Pine 条件得出：

- 存在明确 Pine 阻断：`TradingView 当前不会发送开仓信号`，列出条件名。
- 无阻断但数据不完整：`TradingView 暂时无法完成判断`。
- 前置条件满足、布林形态未成立：`尚未发送开仓信号——等待 PUT/CALL 布林形态`。
- 全部 Pine 条件满足：`TradingView 已具备发送开仓信号的条件`。
- 已在信号记录中匹配到对应 `OPEN_REQUEST`：`TradingView 开仓信号已到达后端`。

第一阶段汇总计数采用四类，不把委托判定混入通过项：

`已通过 N 项 · 交后端 1 项 · 等待触发 N 项 · 阻断 N 项`

### 第二阶段：后端执行判定

第二阶段展示后端权威检查及实际处理结果：

| 状态 | 展示文案 |
| --- | --- |
| 尚未收到 `OPEN_REQUEST` | `等待 TradingView 开仓信号` |
| 尚未收到且后端预检 DVOL 不通过 | `预检：如果现在收到信号，后端将因 DVOL 拒绝执行` |
| 已收到、处理中 | `已收到开仓信号，后端正在检查` |
| 已接受 | `后端已接受，进入选腿与开仓流程` |
| 已拒绝 | `后端已拒绝`，同时显示可展开的拒绝原因 |

后端 DVOL 卡必须同时展示：

- 当前权威分位；
- 完整样本数与要求窗口，例如 `1460 / 1460 根`；
- 当前档位；
- L1 开仓下限及差距；
- 判断来源 `后端 · Deribit DVOL 全历史`。

预检只说明“若现在收到会怎样”，不能伪装成一次已经发生的拒绝。真实信号到达后，以信号记录的 `status` 和 `reject_reason` 为准。

## 页面结构

看板从上到下排列：

1. 总结条：两行同时说明 TradingView 发信状态与后端执行预检。
2. 阶段一卡片：`① TradingView 是否发送开仓信号`。
3. 流程连接状态：未到达时显示“等待信号”，到达后显示接收时间与信号方向。
4. 阶段二卡片：`② 后端收到后是否执行`。
5. 已通过条件折叠区。
6. 数据与判断依据折叠区。

当前未满足、委托判定和等待触发项默认展开；纯通过项默认收起。

## 颜色与标签

- 绿色：条件明确通过、信号已接受。
- 红色：明确阻断或真实拒绝。
- 黄色：等待市场触发或处理中。
- 蓝色：交后端判断、连接正常、信息提示。
- 灰色：数据待定或尚未发生。

“交后端判断”严禁使用绿色；“等待布林触发”严禁使用红色，因为它不是错误。

## 数据流

1. `/api/entry_conditions` 提供最新 Pine 回报和后端条件快照。
2. `/api/signals` 提供真实 `OPEN_REQUEST` 的接收及处理状态。
3. 前端以 Pine 回报计算阶段一，以后端快照显示阶段二预检。
4. 存在真实 `OPEN_REQUEST` 时，阶段二实际结果覆盖预检文案。
5. Pine 回报过期时，阶段一显示“连接回报已过期”，不得用后端数据代替 Pine 发信结论。

## 边界情况

- Pine `tier=-1`：展示“交后端判断”，其余 Pine 条件仍可促成发信。
- Pine 布林形态为空：显示“暂时无法判断”，不能显示“等待触发”。
- PUT 和 CALL 同时未成立：显示两个方向均在等待。
- 后端 DVOL 样本不足：显示“后端暂时无法预检”，不能判为档位 0。
- 信号到达后被其他后端门槛拒绝：展示实际拒绝原因，不继续强调 DVOL 预检。
- 信号与连接回报属于不同 2h K 线：不得错误匹配为同一次触发。

## 验收标准

1. 当前云端示例应显示：Pine 配置/HV/CCI 通过，DVOL 交后端判断，PUT/CALL 布林形态未触发。
2. 当前第一阶段结论应是“尚未发送开仓信号——等待 PUT/CALL 布林形态”。
3. 当前第二阶段应显示“等待 TradingView 开仓信号”，并附预检“DVOL 约 7.3% < 40%，若收到将拒绝”。
4. 页面不得只显示“1 项未满足”，而应分别显示阶段一等待项和阶段二预检阻断。
5. 当模拟布林形态成立且 Pine `tier=-1` 时，阶段一必须允许进入“信号应发送”状态。
6. 当真实开仓信号被拒绝时，阶段二必须显示拒绝原因并可展开详情。
7. 桌面和手机宽度下，两阶段顺序与标签含义保持一致且无横向溢出。
